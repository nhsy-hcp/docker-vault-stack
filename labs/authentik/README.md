# Authentik OIDC Lab

This lab demonstrates how to integrate [Authentik](https://goauthentik.io/) as an OIDC (OpenID Connect) provider for HashiCorp Vault authentication. It showcases multi-namespace authentication, group-based access control, and identity management patterns.

> **Optional lab:** runs as its own compose project on the `docker-vault-stack` network; start the core stack first.

## Overview

What this lab demonstrates:

- **Authentik Stack**: OAuth2/OIDC provider (v2026.8.3) with PostgreSQL backend; no Redis required (simplified deployment)
- **Vault Namespaces**: Root, admin, and tenant (tn001) with OIDC authentication in the root and admin namespaces
- **Identity Groups**: External and internal groups for group-based access control with policy templates
- **Sample Secrets**: KV secrets for testing permissions
- Automated admin user creation and API token generation
- Complete Terraform automation
- Network-aware configuration for Docker environments

### Architecture

```text
┌─────────────────────────────────────────────────────────────────┐
│                     Docker Compose Stack                        │
├─────────────────────────────────────────────────────────────────┤
│  ┌──────────────────┐         ┌──────────────────┐              │
│  │   Authentik      │         │  PostgreSQL      │              │
│  │   Port: 9000     │◄────────┤  Port: 5432      │              │
│  └──────────────────┘         └──────────────────┘              │
│           │ OIDC                                                │
│           ▼                                                     │
│  ┌──────────────────┐                                           │
│  │   Vault          │                                           │
│  │   Port: 8200     │                                           │
│  └──────────────────┘                                           │
└─────────────────────────────────────────────────────────────────┘

Authentication Flow: User → Vault → Authentik Login → Group Mapping → Token

Namespace Structure:
Root (/)
├── OIDC Auth: vault-admin group
└── Admin (/admin)
    ├── OIDC Auth: vault-user group
    └── Tenant (/admin/tn001)
        └── KV Secrets: team1/*
```

## Prerequisites

- Core stack running and unsealed (see the [root README](../../README.md))
- Authentik environment variables in the **project root `.env` file** (not in `labs/authentik/`):

```bash
# Authentik Configuration
AUTHENTIK_SECRET_KEY=<generate with: openssl rand -base64 32>
AUTHENTIK_ADMIN_USER=akadmin
AUTHENTIK_ADMIN_PASSWORD=<REQUIRED - set your admin password>

# PostgreSQL Configuration
PG_PASS=<generate with: openssl rand -base64 24>
PG_USER=authentik
PG_DB=authentik

# Authentik Provider (used by Terraform)
AUTHENTIK_URL=http://authentik.localhost:9000
AUTHENTIK_TOKEN=<auto-generated by setup-admin.sh>
```

- `AUTHENTIK_ADMIN_PASSWORD` **must** be set before running setup
- `AUTHENTIK_TOKEN` is auto-generated - do not set manually
- Vault variables (`VAULT_ADDR`, `VAULT_TOKEN`) are already in root `.env`
- No manual `/etc/hosts` entry is required for the Authentik lab alias flow

## Quick Start

```bash
# From project root
task up                  # Start the core stack (creates the shared network)
task authentik:all       # Start Authentik + complete setup (admin + terraform)
```

`task authentik:all` runs:

1. `task authentik:up` - Starts Authentik services on the shared network
2. `scripts/setup-admin.sh` - Creates admin user and generates API token
3. `terraform init` - Initializes Terraform providers
4. `terraform apply` - Configures Vault OIDC

## Usage

### Access Authentik

- Authentik UI: http://authentik.localhost:9000
- Login: Username from `AUTHENTIK_ADMIN_USER`, password from `AUTHENTIK_ADMIN_PASSWORD`

### Verify Deployment

```bash
task authentik:status    # Check services
task authentik:health    # Health checks
vault namespace list     # Verify namespaces
```

### Root Namespace Admin Access

```bash
# Login as vaultadmin (vault-admin group)
vault login -method=oidc -path=authentik-oidc role=default

# Or use demo script
task authentik:test-auth

# Verify admin access
vault namespace list
vault policy list
vault auth list
```

### Admin Namespace User Access

```bash
# Login as testuser1 (vault-user group)
vault login -namespace=admin -method=oidc -path=authentik-oidc role=default

# Verify limited access
vault namespace list -namespace=admin
vault kv list -namespace=admin/tn001 team1
```

### Read Team Secrets

```bash
# As testuser1 (vault-tn001-team1-reader group)
vault kv get -namespace=admin/tn001 team1/app1
vault kv get -namespace=admin/tn001 team1/app2
```

### Verify Group Membership

```bash
# Check current token
vault token lookup

# View entity details
ENTITY_ID=$(vault token lookup -format=json | jq -r '.data.entity_id')
vault read identity/entity/id/$ENTITY_ID

# Or use helper script
task authentik:check-policies
```

## Configuration

### Authentik Groups

| Group | Description | Vault Access |
|-------|-------------|--------------|
| `vault-admin` | Full administrators | Root namespace, all permissions |
| `vault-user` | Standard users | Admin namespace, default access |
| `vault-tn001-team1-reader` | Team 1 readers | Tenant namespace, read-only to team1/* |
| `vault-tn001-team2-reader` | Team 2 readers | Tenant namespace, read-only to team2/* |

### Identity Groups

**External Groups** (linked to Authentik, in the admin namespace):

- `authentik-oidc-vault-tn001-team1-reader-external` → `vault-tn001-team1-reader` group
- `authentik-oidc-vault-tn001-team2-reader-external` → `vault-tn001-team2-reader` group

**Internal Groups** (Vault-managed, in the admin/tn001 namespace):

- `authentik-oidc-vault-tn001-team1-reader-internal` → Inherits from external group
- `authentik-oidc-vault-tn001-team2-reader-internal` → Inherits from external group

### OIDC Configuration

- **Mount Path**: `authentik-oidc` (root and admin namespaces, variable `vault_oidc_mount_path`), role `default`
- **Scopes**: `openid`, `profile`, `email`, `groups`
- **Claims**: `email` (user identifier), `groups` (group membership)
- **Redirect URIs**: CLI (`http://localhost:8250/oidc/callback`), UI (`http://localhost:8200/ui/vault/auth/authentik-oidc/oidc/callback` and `http://vault.localhost:8200/ui/vault/auth/authentik-oidc/oidc/callback`)

### Network Configuration

The Docker stack exposes localhost-style aliases, and all services communicate on the `docker-vault-stack` network. This lab uses `authentik.localhost:9000` for host and browser access, and as the Vault OIDC discovery default.

| Context | URL | Reason |
|---------|-----|--------|
| **Terraform Provider** | `http://authentik.localhost:9000` | Uses the localhost-style alias exposed by Docker |
| **Vault OIDC Config** | `http://authentik.localhost:9000` | Uses the configured network alias default |
| **Browser Access** | `http://authentik.localhost:9000` | Consistent browser-friendly hostname |

### Security Considerations

- TLS verification disabled for local development
- Change default passwords for production use
- Rotate API tokens regularly

## Troubleshooting

### Authentik Alias Not Resolving

**Symptom:** OIDC authentication fails with redirect URI or hostname resolution errors.

**Solution:**

```bash
curl -I http://authentik.localhost:9000
docker compose --env-file ../../.env -f compose.yaml config
task authentik:status
```

### Authentik Not Starting

```bash
task authentik:logs              # All services
task authentik:logs-server       # Authentik only
task authentik:logs-postgres     # PostgreSQL only
task authentik:restart           # Restart services
```

### OIDC Discovery URL Not Accessible

```bash
# Verify Authentik is running
curl -k http://authentik.localhost:9000/-/health/live/

# Check OIDC configuration
curl -k http://authentik.localhost:9000/application/o/vault/.well-known/openid-configuration

# Check compose service state
task authentik:status
```

### Authentication Fails

```bash
# Verify OIDC mount exists
vault auth list
vault auth list -namespace=admin

# Check OIDC configuration
vault read auth/authentik-oidc/config
vault read -namespace=admin auth/authentik-oidc/config

# Verify group membership in Authentik UI
# Admin Interface > Directory > Groups
```

### Group Mapping Not Working

```bash
# Check identity groups
vault list identity/group/name
vault list -namespace=admin identity/group/name

# Verify entity after login
ENTITY_ID=$(vault token lookup -format=json | jq -r '.data.entity_id')
vault read identity/entity/id/$ENTITY_ID
```

### Terraform Errors

```bash
terraform refresh    # Refresh state
terraform plan       # Check for drift
terraform apply      # Re-apply if needed
```

### Network Issues

```bash
# Verify Docker network
docker network ls | grep docker-vault-stack
docker network inspect docker-vault-stack

# Verify alias-based access from host
curl -I http://authentik.localhost:9000
```
