# PKI Lab

Vault's PKI secrets engine with two imported intermediate CAs, issuer-aware AIA/CRL URLs, ACME and certificate management tasks. Private keys are stored in Terraform state, so this setup is **not** suitable for production.

> **Namespace:** everything is deployed into `admin/tn001` (mount `admin/tn001/pki`).

## Overview

What this lab demonstrates:
- A root CA generated by Terraform (self-signed, never imported into Vault)
- Two intermediate CAs (v1 and v2) imported into Vault as named issuers, with single-apply rotation
- Templated AIA / CRL / OCSP URLs that include the namespace path
- An ACME server on the mount with External Account Binding required
- Certificate roles with different restrictions, plus auto-tidy

### Architecture

```text
Root CA (Self-Signed, 1 year validity)
├── Intermediate CA v1 (90 days validity) ── default issuer
│   ├── Certificate Role: default (1-24 hour certificates, ACME)
│   └── Certificate Role: v1      (1-24 hour certificates)
└── Intermediate CA v2 (90 days validity)
    └── Certificate Role: v2      (1-24 hour certificates, stricter)
```

## Prerequisites

- Core stack running and unsealed (see the [root README](../../README.md))
- Namespace `admin/tn001` - create it with `task namespaces` from the repo root (not created by default)
- Terraform >= 1.5, Vault CLI, `task`, `jq`, OpenSSL
- Docker (ACME demo only)

## Quick Start

The lab Taskfile is included in the root `Taskfile.yml` as `pki`, so run everything from the repo root (the root Taskfile loads `.env`):

```bash
task namespaces        # admin, admin/tn001 (idempotent)
task pki:tf:init
task pki:tf:apply
task pki:test          # smoke tests: issuance, chains, role limits, CSR signing, CRL, ACME
```

Running inside `labs/pki` also works (`task tf:apply`, ...) after `source ../../.env`. The Vault CLI examples below assume:

```bash
source .env
export VAULT_NAMESPACE=admin/tn001
```

## Usage

### Issue Certificates

```bash
task pki:default-cert  # default role (default issuer - v1)
task pki:v1-cert       # v1 issuer explicitly
task pki:v2-cert       # v2 issuer

vault write pki/issue/default \
    common_name="app.example.com" \
    alt_names="api.example.com,web.example.com" \
    ip_sans="127.0.0.1" \
    format=pem
```

### Sign a CSR

```bash
task pki:sign CN=app.example.com ROLE=v2   # CSR, key and certificate saved in labs/pki/.tmp/
```

### Inspect and Revoke Certificates

```bash
vault list pki/certs
vault read -field=certificate pki/cert/<serial> | openssl x509 -text -noout
vault write pki/revoke serial_number="<serial>"
```

### View Issuers

```bash
vault list pki/issuers
vault read pki/issuer/<issuer_id>
vault read -field=certificate pki/issuer/<issuer_id> | openssl x509 -text -noout
```

### Switch Default Issuer

To change the default issuer from v1 to v2, edit `pki.tf` and run `task pki:tf:apply`:

```hcl
resource "vault_pki_secret_backend_config_issuers" "config" {
  namespace                     = var.vault_namespace
  backend                       = vault_mount.pki.path
  default                       = vault_pki_secret_backend_issuer.intermediate_v2.issuer_id
  default_follows_latest_issuer = false
}
```

### Health Check

```bash
vault pki health-check pki
vault pki health-check -issuer=<issuer_id> pki
```

### ACME

Request certificates with certbot over HTTP-01 - see [acme-demo.md](acme-demo.md).

## Configuration

### Namespace Handling

The namespace is set once in `labs/pki/Taskfile.yml` (`vars.NAMESPACE`) and exported to every PKI task (via the `ns_env` anchor, not top-level `env`, so it does not leak into root tasks) as:
- `VAULT_NAMESPACE` - used by all Vault CLI tasks
- `TF_VAR_vault_namespace` - used by Terraform (`var.vault_namespace`)

Terraform resources set `namespace = var.vault_namespace`, which the Vault provider treats as **relative to the provider namespace**. The `tf:*` tasks therefore run Terraform with `VAULT_NAMESPACE` unset; running `terraform` directly with `VAULT_NAMESPACE=admin/tn001` exported would target `admin/tn001/admin/tn001`.

### Certificate Authorities (`tls.tf`)

- **Root CA**: self-signed, 1-year validity
- **Intermediate v1 / v2**: signed by the root CA, 90-day validity
- All CAs use 4096-bit RSA keys; certificates are written to `certs/` and printed on change

When the intermediates expire, `terraform apply` renews them. The re-imported bundle triggers replacement of the matching `vault_pki_secret_backend_issuer` (`replace_triggered_by`), so the issuer name moves to the new issuer in a single apply.

### Vault PKI (`pki.tf`)

- **Mount**: `admin/tn001/pki`, 90-day max TTL, ACME response headers (`Link`, `Location`, `Replay-Nonce`) allowed, non-sensitive PKI fields excluded from audit HMAC
- **Import**: intermediate CA bundles (cert + key) via `issuers/import/bundle`
- **Issuers**: `intermediate-ca-v1` (default) and `intermediate-ca-v2`
- **Cluster config**: `config/cluster` path and AIA path set to `${vault_cluster_addr}/v1/${vault_namespace}/pki`
- **URLs**: templated per issuer
  - Issuing certificate: `{{cluster_aia_path}}/issuer/{{issuer_id}}/der`
  - CRL: `{{cluster_aia_path}}/issuer/{{issuer_id}}/crl/der`
  - OCSP: `{{cluster_path}}/ocsp`
- **ACME**: enabled, `default_directory_policy = role:default`, `eab_policy = always-required`
- **Auto-tidy**: cert store, revoked certs and ACME state every hour

### Certificate Roles

| Role | Issuer | Domains | localhost | Wildcards |
|------|--------|---------|-----------|-----------|
| `default` | default issuer (v1) | `example.com` + subdomains | yes | yes |
| `v1` | intermediate v1 | `example.com` + subdomains | yes | yes |
| `v2` | intermediate v2 | `example.com` + subdomains | no | no |

All roles require 4096-bit RSA keys, issue `ServerAuth` certificates and generate leases.

### Variables

| Variable | Default | Description |
|----------|---------|-------------|
| `vault_namespace` | `admin/tn001` | Namespace hosting the PKI mount (set via `TF_VAR_vault_namespace` by the Taskfile) |
| `vault_cluster_addr` | `http://vault.localhost:8200` | Vault address used in AIA/CRL/OCSP/ACME URLs |
| `organization_name` | `ACME Corp` | Organization in CA subjects |

### Outputs

| Output | Description |
|--------|-------------|
| `pki_mount_path` | PKI mount path |
| `intermediate_v1_issuer_id` / `intermediate_v2_issuer_id` | Issuer IDs |
| `certificate_roles` | Map of role name to issue endpoint |
| `acme_directory` | ACME directory URL |
| `root_certificate_pem`, `intermediate_v*_certificate_pem` | CA certificates (sensitive) |

## Troubleshooting

### Resources Created in the Wrong Namespace

Run Terraform via `task pki:tf:*`, or `unset VAULT_NAMESPACE` before running `terraform` directly (see [Namespace Handling](#namespace-handling)).

### Issuance Fails With an Expired Issuer

The intermediates are valid for 90 days; run `task pki:tf:apply` to renew them.

### `notBefore before signer's notBefore` Right After Apply

Vault backdates leaf certificates by 30s (`not_before_duration`), and freshly created intermediates start "now". Wait ~30s after deploying; `task pki:test` waits for this automatically.

### Health Check Findings on a Fresh Mount

"Tidy hasn't run" (critical) clears after the first hourly auto-tidy. "ACME ... not using an https scheme" is expected because the lab runs Vault without TLS (ACME still works over HTTP here).

### Certificate Import or Chain Issues

```bash
openssl x509 -in labs/pki/certs/intermediate-v1.pem -text -noout
openssl verify -CAfile labs/pki/certs/root-ca.pem labs/pki/certs/intermediate-v1.pem
openssl verify -CAfile labs/pki/certs/root-ca.pem -untrusted labs/pki/certs/intermediate-v1.pem \
  <(vault write -field=certificate pki/issue/v1 common_name="test.example.com" ttl=1m)
```

### Role Configuration Errors

```bash
vault read pki/roles/default
vault write -f pki/issue/default common_name=test.example.com
```

### CRL Issues

```bash
vault write pki/crl/rotate
curl -s "$VAULT_ADDR/v1/admin/tn001/pki/crl/pem" | openssl crl -text -noout
vault read sys/mounts/pki
```

```bash
task pki:acme:down            # stop ACME demo containers
task pki:acme:certbot:clean   # remove certbot state
task pki:pki-clean            # destroy the PKI mount and clean Terraform state
```
