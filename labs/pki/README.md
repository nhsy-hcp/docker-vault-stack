# PKI Lab - HashiCorp Vault PKI Secrets Engine

This lab demonstrates HashiCorp Vault's PKI secrets engine with multiple imported intermediate Certificate Authorities (CAs), issuer-aware AIA/CRL URLs, ACME, and certificate management tasks.

Everything is deployed into the Vault Enterprise namespace **`admin/tn001`** (mount `admin/tn001/pki`).

Private TLS keys are stored in Terraform state and are **NOT** suitable for production use.

## Lab Overview

This lab sets up a complete PKI hierarchy with:
- A Root Certificate Authority (self-signed, generated by Terraform, never imported into Vault)
- Two Intermediate Certificate Authorities (v1 and v2) imported into Vault as issuers
- Templated AIA / CRL / OCSP URLs that include the namespace path
- ACME server on the mount (External Account Binding required)
- Certificate roles for different use cases, plus auto-tidy

### Architecture

```
Root CA (Self-Signed, 1 year validity)
├── Intermediate CA v1 (90 days validity) ── default issuer
│   ├── Certificate Role: default (1-24 hour certificates, ACME)
│   └── Certificate Role: v1      (1-24 hour certificates)
└── Intermediate CA v2 (90 days validity)
    └── Certificate Role: v2      (1-24 hour certificates, stricter)
```

## Prerequisites

- Core stack running and unsealed (`task up`, `task unseal` from the repo root)
- Namespace `admin/tn001` exists
- Terraform >= 1.5, Vault CLI, `task`, `jq`, OpenSSL
- Docker (ACME demo only)

## Quick Start

The lab Taskfile loads the root `../../.env` (`VAULT_ADDR`, `VAULT_TOKEN`), so no lab-local `.env` is needed.

```bash
cd labs/pki
task tf:init
task tf:plan
task tf:apply

# Smoke test: issuance per role, chain validation, role limits, CSR signing, CRL, ACME
task test

# Issue test certificates
task default-cert   # default role (default issuer - v1)
task v1-cert        # v1 issuer explicitly
task v2-cert        # v2 issuer
```

### Namespace

The namespace is set once in `Taskfile.yml` (`vars.NAMESPACE`) and exported as:
- `VAULT_NAMESPACE` - used by all Vault CLI tasks
- `TF_VAR_vault_namespace` - used by Terraform (`var.vault_namespace`)

Terraform resources set `namespace = var.vault_namespace`, which the Vault provider treats as **relative to the provider namespace**. The `tf:*` tasks therefore run Terraform with `VAULT_NAMESPACE` unset; running `terraform` directly with `VAULT_NAMESPACE=admin/tn001` exported would target `admin/tn001/admin/tn001`.

The CLI examples below assume:

```bash
source ../../.env
export VAULT_NAMESPACE=admin/tn001
```

## Key Components

### 1. Certificate Authority Generation (`tls.tf`)

- **Root CA**: Self-signed certificate with 1-year validity
- **Intermediate v1 / v2**: Signed by Root CA, 90-day validity
- All CAs use 4096-bit RSA keys; certificates are written to `certs/` and printed on change

When the intermediates approach expiry, `terraform apply` renews them. The re-imported bundle triggers replacement of the matching `vault_pki_secret_backend_issuer` (`replace_triggered_by`), so the issuer name moves to the new issuer in a single apply.

### 2. Vault PKI Configuration (`pki.tf`)

- **PKI Mount**: `admin/tn001/pki`, 90-day max TTL, ACME response headers (`Link`, `Location`, `Replay-Nonce`) allowed, non-sensitive PKI fields excluded from audit HMAC
- **Certificate Import**: Imports intermediate CA bundles (cert + key) via `issuers/import/bundle`
- **Issuer Configuration**: Named issuers `intermediate-ca-v1` and `intermediate-ca-v2`, v1 is default
- **Cluster config**: `config/cluster` path and AIA path set to `${vault_cluster_addr}/v1/${vault_namespace}/pki`
- **URL Configuration**: Templated per-issuer URLs:
  - Issuing certificate: `{{cluster_aia_path}}/issuer/{{issuer_id}}/der`
  - CRL: `{{cluster_aia_path}}/issuer/{{issuer_id}}/crl/der`
  - OCSP: `{{cluster_path}}/ocsp`
- **ACME**: Enabled, `default_directory_policy = role:default`, `eab_policy = always-required`
- **Auto-tidy**: Cert store, revoked certs and ACME state every hour

### 3. Certificate Roles

| Role | Issuer | Domains | localhost | Wildcards |
|------|--------|---------|-----------|-----------|
| `default` | default issuer (v1) | `example.com` + subdomains | yes | yes |
| `v1` | intermediate v1 | `example.com` + subdomains | yes | yes |
| `v2` | intermediate v2 | `example.com` + subdomains | no | no |

All roles require 4096-bit RSA keys, issue `ServerAuth` certificates and generate leases.

## Certificate Operations

### Issue a Certificate

```bash
vault write pki/issue/default \
    common_name="app.example.com" \
    alt_names="api.example.com,web.example.com" \
    ip_sans="127.0.0.1" \
    format=pem

# Using specific issuer
vault write pki/issue/v1 common_name="test.example.com"
```

### Revoke a Certificate

```bash
vault list pki/certs
vault write pki/revoke serial_number="<serial>"
```

### Certificate Inspection

```bash
vault read pki/cert/<serial>
vault read -field=certificate pki/cert/<serial> | openssl x509 -text -noout
```

## Issuer Management

### Switch Default Issuer

To change the default issuer from v1 to v2, edit `pki.tf`:

```hcl
resource "vault_pki_secret_backend_config_issuers" "config" {
  namespace                     = var.vault_namespace
  backend                       = vault_mount.pki.path
  default                       = vault_pki_secret_backend_issuer.intermediate_v2.issuer_id
  default_follows_latest_issuer = false
}
```

Then run `task tf:apply`.

### View Issuer Information

```bash
vault list pki/issuers
vault read pki/issuer/<issuer_id>
vault read -field=certificate pki/issuer/<issuer_id> | openssl x509 -text -noout
```

## Monitoring and Maintenance

```bash
# PKI health check
vault pki health-check pki

# Check specific issuer

```

## Troubleshooting

1. **Resources created in the wrong namespace** - run Terraform via `task tf:*`, or `unset VAULT_NAMESPACE` before running `terraform` directly (see [Namespace](#namespace)).

2. **Issuance fails with an expired issuer** - the intermediates are valid for 90 days; run `task tf:apply` to renew them.

3. **Certificate import / chain issues**
   ```bash
   openssl x509 -in certs/intermediate-v1.pem -text -noout
   openssl verify -CAfile certs/root-ca.pem certs/intermediate-v1.pem
   openssl verify -CAfile certs/root-ca.pem -untrusted certs/intermediate-v1.pem \
     <(vault write -field=certificate pki/issue/v1 common_name="test.example.com" ttl=1m)
   ```

4. **Role configuration errors**
   ```bash
   vault read pki/roles/default
   vault write -f pki/issue/default common_name=test.example.com
   ```

5. **CRL issues**
   ```bash
   vault write pki/crl/rotate
   curl -s "$VAULT_ADDR/v1/admin/tn001/pki/crl/pem" | openssl crl -text -noout
   ```
